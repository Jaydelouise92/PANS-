## 2026-07-21 - Form Control Label Wrapping and Accessibility Links
**Learning:** HTML nested label wrapping (e.g. `<label><span>Label</span><input /></label>`) can sometimes cause accessibility and screen-reader mapping problems, especially when validation errors are also placed inside or outside the label without explicit programmatic associations. Refactoring these fields into standalone containers with an explicit `<label htmlFor={id}>` coupled with `aria-invalid` and `aria-describedby` linked to validation elements (marked with `role="alert"`) ensures a much more robust and compliant screen-reader experience.
**Action:** Use standalone containers with explicit `htmlFor` and `id` linking, along with programmatic error association, rather than relying on automatic nested label mapping.

## 2026-07-22 - Explicit ARIA Labels for Floating Interactive Controllers and Checkbox Refactoring
**Learning:** Floating controller widgets (like BackgroundMusic and VoiceAssistant) that use icon-only triggers must have explicit ARIA labels (`aria-label`, `aria-pressed`, `aria-expanded`) and elegant keyboard focus rings (`focus-visible:...`) to be completely keyboard accessible and visible/interpretable by screen readers. Furthermore, separating nested `<label>` wrappers of checkbox items into discrete programmatic label-input linkages resolves accessibility warnings and prevents unintended click event propagation.
**Action:** Ensure all icon-only control triggers have dedicated `aria-label`, state tracking attributes, clear focus classes, and split nested label structures into distinct programmatic bindings.
